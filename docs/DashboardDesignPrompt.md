# 사이(Sai) B2B 웹 대시보드 — 디자인 요청 프롬프트

> 클로드 디자인(claude.ai/design)에 그대로 붙여넣을 수 있는 브리프입니다.

---

## 배경

"사이(Sai)"는 크롬 확장 기반 글로벌 업무 메시지 AI 교정 도구입니다. 이 확장을 쓰는
팀을 위해, 팀 리더가 보는 **B2B 웹 대시보드**를 별도 웹페이지로 만들려고 합니다.
확장이 감지한 "협업 마찰"(오해 소지 표현, 하소연 감지, 오프타임 강행 전송 시도 등)을
팀 단위로 집계해, 조직의 소통 건강도를 한눈에 보여주는 화면입니다.

지금은 동작하는 React 프로토타입이 있지만(기능은 맞고 비주얼 디자인이 약함),
**시각 디자인을 새로 받고 싶습니다.** 기능·데이터 구조는 고정이고, 레이아웃·타이포·
색 활용·정보 위계·인터랙션 디테일을 다시 설계해 주세요.

## 절대 지켜야 할 제약 (기능·데이터 — 협상 불가)

1. **개인 점수 표기 금지.** 이 대시보드에 나오는 모든 수치는 **팀/조직 단위 집계**입니다.
   특정 개인의 이름·계정·식별자가 들어가는 요소를 만들지 마세요. "누가 하소연했는지"가
   아니라 "하소연으로 감지된 메시지가 몇 건인지"만 다룹니다.
2. **EU·특정 국가를 전제하지 않습니다.** 카피·아이콘·지도 이미지 어디에도 특정 지역을
   기본값처럼 다루는 표현을 넣지 마세요.
3. **v1은 목업 데이터**임을 화면에 숨기지 않습니다 — "데모용 목업 데이터입니다" 같은
   안내를 상단에 눈에 띄게 유지해 주세요.
4. **Zero Retention 안내** — "메시지 본문은 저장되지 않습니다" 문구를 하단에 유지합니다.
5. 다크 모드를 지원합니다(라이트/다크 둘 다 시안 필요).

## 화면에 반드시 있어야 하는 요소

1. **헤더** — 로고/브랜드명 + 다크모드 토글.
2. **목업 데이터 안내 배너** (제약 3 참조).
3. **Health Index 히어로 수치** — 화면에서 가장 큰 단일 숫자. 공식은
   `Health Index = 100 - 마찰 비율(%)` 이며, 이 공식을 캡션으로 함께 보여줍니다.
   (지금은 큰 숫자 하나뿐인데, 여기에 **게이지/링 형태 시각화**를 추가해도 좋습니다 —
   0~100 범위를 직관적으로 보여줄 수 있으면 자유롭게 제안해 주세요.)
4. **긍정 신호 vs 마찰 신호 비교 차트** — 지금은 발산형(diverging/mirror) 막대 그래프로
   구현되어 있습니다: 0을 기준으로 긍정 신호(예: "제때 회신함", "명확한 요청으로 교정됨",
   "예약 제안을 수락함")는 한쪽으로, 마찰 신호(예: "오해 소지 표현 발생", "하소연으로
   감지된 메시지", "오프타임 강행 시도")는 반대쪽으로 뻗어나갑니다. 각 항목은 라벨 +
   건수 + 짧은 설명 텍스트를 가집니다. **이 발산형 구조(양수/음수를 한 축에서 대비)는
   유지**하되, 표현 방식(막대/도넛/다른 형태)은 제안 환영합니다.
5. **범례** — 긍정/마찰 두 계열을 색으로 구분하는 범례. 색만으로 구분하지 않고 항상
   라벨이 같이 보여야 합니다(색맹 접근성).
6. **표 보기 전환** — 차트와 같은 데이터를 표(테이블) 형태로도 볼 수 있는 토글.
   시각 장애/저시력 사용자를 위한 대안 뷰입니다.
7. **Zero Retention 안내** (제약 4 참조), 푸터.

## 데이터 항목 (그대로 유지, 값은 목업)

| 구분 | 항목 | 설명 |
|---|---|---|
| 긍정 | 제때 회신함 | 평균 응답까지 3시간 이내 |
| 긍정 | 명확한 요청으로 교정됨 | 오해 소지 표현이 교정 과정에서 정리됨 |
| 긍정 | 예약 제안을 수락함 | 오프타임 전송 대신 예약을 선택 |
| 마찰 | 오해 소지 표현 발생 | 교정 전 원문 기준, 교정 후 반영됨 |
| 마찰 | 하소연으로 감지된 메시지 | 반복된 불만·피로감 표현 — 메시지 단위 집계 |
| 마찰 | 오프타임 강행 시도 | 긴급도를 올려 예약 제한을 우회 |

## 브랜드 가이드

- **주 색상**: 주황 `#ff6b00`(긴급/마찰 신호 계열), 초록 `#10b981`(긍정/승인 계열).
  이 두 색은 확장 본체·사이드패널과 이미 통일되어 있으니 색상 자체는 유지해 주세요
  (배색 활용 방식·톤·틴트는 자유롭게 재설계해도 됩니다).
- **폰트**: Pretendard(한글 가변 폰트) 우선, 없으면 시스템 산세리프 폴백.
- **톤**: 업무 도구답게 차분하고 신뢰감 있게. 과장된 게이미피케이션(뱃지·컨페티 등)은
  피해 주세요 — "협업 건강도"라는 주제 특성상 개인을 평가·감시하는 느낌을 주면 안 됩니다.
- 라이트 배경 `#eef0f3`(페이지) / `#ffffff`(카드), 다크 배경 `#0e1116`(페이지) /
  `#1a1f27`(카드) — 참고용이며 새 팔레트 제안도 환영합니다.

## 기술 제약 (구현 시 고려)

- **React**로 구현됩니다(Vite). 순수 HTML/CSS/SVG로 표현 가능한 디자인이면 이식이
  쉽습니다 — 무거운 차트 라이브러리나 애니메이션 프레임워크 의존은 피해 주세요.
- 확장(크롬 익스텐션)과 **완전히 분리된 별도 웹페이지**로 배포됩니다(Firebase Hosting).
  즉 화면 폭은 데스크톱 브라우저 창 기준(모바일 대응은 nice-to-have).
- 접근성: 계열 색만으로 정보를 구분하지 않기, 표 보기 대안 유지, 다크모드 대비 확보.

## 산출물로 원하는 것

- 라이트/다크 모드 각각의 전체 화면 시안
- 위 6개 요소의 배치·비주얼 스타일이 명확히 드러나는 정도의 완성도
- (가능하면) 발산형 차트가 값이 0에 가까운 항목/큰 항목일 때 어떻게 보이는지 예시 2종
