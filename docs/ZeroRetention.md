# Zero Retention 리뷰 체크리스트 (S08 / Spec 필수 5 · audit 7)

> 이 문서는 **코드 리뷰 게이트**다. 아래 항목 중 하나라도 ✕면 머지하지 않는다.
> 자동 검증은 `test/zeroRetention.test.js`가 한다 — 이 문서는 **테스트가 못 잡는 것**을 위한 것이다.

## 금지 (다른 모든 편의보다 우선)

- 메시지 **본문·교정문·수정문**을 Firestore·Functions 로그·`chrome.storage` 어디에도 쓰지 않는다.
- 상류(LLM·네트워크) **에러 메시지를 그대로 로그·응답에 싣지 않는다** — 본문이 섞여 올 수 있다.
- 스키마 검증 실패 정보를 만들 때 **위반한 값**을 담지 않는다. 담는 것은 `필드:사유` 코드뿐.
- "디버깅 중이니 잠깐만" 로그도 금지. 잠깐이 남는다.

## 판정표 — 무엇이 위반인가

| 조건 | 판정 |
|---|---|
| 본문이 Firestore 문서에 기록됨 | ✕ 위반 |
| 본문이 Functions 로그(`console.*`/logger)로 나감 | ✕ 위반 |
| 본문 조각이 에러 메시지·스택에 실려 로그로 나감 | ✕ 위반 |
| 본문이 `chrome.storage`에 **자동으로** 영속됨 | ✕ 위반 |
| 사용자가 **버튼을 눌러 직접 저장한** 문장이 `chrome.storage`에만 남음 (스니펫 — 권장 10) | ✓ 허용 — 아래 단서 참조 |
| 본문이 **프로세스 메모리에만** 존재(요청 처리 중·TTL 캐시) | ✓ 허용 — 처리하려면 불가피 |
| 카운트·수치·불리언·enum·타임스탬프만 기록 | ✓ 허용 |
| 사용자가 **직접 입력한 설정값**(용어집·수신자·프로필) 저장 | ✓ 허용 — 메시지 본문이 아니다 |
| 본문을 입력으로 한 **해시**(캐시 키) | ✓ 허용 — 되돌릴 수 없다 |
| **제3자가 쓴 본문**(직전 대화 맥락 — 권장 8)이 `chrome.storage`에 남음 | ✕ 위반 — 스니펫 단서가 적용되지 않는다 (아래 참조) |
| 제3자가 쓴 본문이 **요청으로만** 흘러가고 저장·로그에 남지 않음 | ✓ 허용 — 처리하려면 불가피 |

### 주의: Firestore 규칙은 "아직 없는 코드"를 위한 방어선

현재 **Firestore에 쓰는 코드가 하나도 없다.** `firestore.rules`의 필드 화이트리스트·길이 상한은
나중에 누군가 쓰기를 추가할 때를 대비한 방어선이다 — 규칙이 있다는 사실이 "지금 안전하다"의
근거는 아니며, 반대로 쓰기를 추가하는 순간 규칙이 1차 방어선이 된다.

### 단서: 스니펫(권장 10)은 왜 위반이 아닌가

Zero Retention이 막으려는 것은 **사용자가 요청하지도 않았는데 시스템이 본문을 남기는 것**이다.
스니펫은 사용자가 `[스니펫 저장]`을 눌러 **자기 문장을 자기 기기에** 두는 것이라 성격이 다르다
(메모장에 붙여넣는 것과 같다). 다만 그 구분이 성립하려면 **세 조건이 전부** 지켜져야 하며,
하나라도 깨지면 그 순간 위반이 된다:

1. **사용자의 명시적 행동으로만** 저장된다 — 자동 저장·"최근 교정문" 히스토리는 금지.
2. **`chrome.storage.local`에만** 남는다 — 🔴 Firestore·서버·`chrome.storage.sync` 전송 금지
   (sync는 구글 계정을 통해 기기 밖으로 나간다).
3. 사용자가 **언제든 개별 삭제**할 수 있다.

### 주의: 직전 대화 맥락(권장 8 · S21)은 **남이 쓴 본문**이다 — 저장 금지

S21은 같은 화면의 직전 메시지 최대 5개를 교정 요청에 함께 싣는다. 이것은 스니펫·예약과 성격이
**다르다**: 스니펫이 허용되는 근거는 "사용자가 **자기 문장**을 자기 기기에 직접 남긴다"인데,
맥락은 **제3자가 쓴 문장**이라 그 근거가 통째로 성립하지 않는다. 따라서 예외 없이 다음을 지킨다.

| 경계 | 규칙 | 확인 |
|---|---|---|
| `chrome.storage` | 🔴 **본문 저장 금지.** 저장되는 것은 on/off 불리언 1개(`sai.threadContext`)뿐 | `threadContext.js`가 `storage.js`를 import하지 않는다 |
| 서버 로그 | 건수만 (`threadContextCount`) | `test/threadContext.unit.test.js` — 본문 문자열 부재를 실제로 검사 |
| 응답 | 건수만 — 맥락 본문을 되돌려주지 않는다 | 같은 테스트 |
| 화면 | React state로만 존재, 팝업이 닫히면 사라진다 | `SaiOverlay.jsx` — 전송용은 ref, 표시용은 state |
| 민감정보 | 맥락에 키·카드번호가 있으면 **마스킹 후** 전송 (필수 11) | `selectThreadMessages()`가 `redact()` 적용 |

🔴 이 기능은 **끌 수 있어야 한다** — 사용자가 남의 메시지를 보내지 않기로 선택할 권리가 있다
(Spec 권장 8이 "끄기 가능"을 요구하는 이유이기도 하다). 팝업과 사이드패널 설정 양쪽에 스위치가 있다.

### 주의: 캐시는 본문 파생 텍스트를 들고 있다

`MemoryCacheStore`는 교정 결과(`refined`·`backTranslation`)를 TTL 동안 메모리에 보관한다.
디스크·DB에 쓰지 않고 프로세스가 죽으면 사라지므로 판정표상 허용이다. 🔴 **이 캐시를 Redis·
Firestore 같은 외부 저장소로 바꾸는 순간 Zero Retention 위반이 된다** — 교체하려면 값에서
본문 파생 필드를 빼는 설계가 먼저다.
