🔴 **그래도 「모델 교체 구조」는 말할 가치가 있다** — 이게 실제로 값을 한 사례이기 때문이다.

> **"모델은 갈아 끼울 수 있게 만들었고, 실제로 개발 중에 한 번 갈아 끼웠습니다."**

질문받으면: *"개발 중에는 한도 때문에 Gemini를 썼고 지금은 OpenAI입니다. 교체 지점이 한
파일이라 프롬프트·검증 로직은 그대로 두고 provider만 바꿨습니다."*

🔴 **덤으로 얻은 것 하나** — Gemini에서 프롬프트를 4번 고쳐도 못 잡던 **역번역 언어 오류**가
OpenAI에서는 대부분 사라졌다. 다만 **한→일에서는 여전히 재현된다**(2026-08-17 실측). 그래서
6번 슬라이드의 「역번역이 내 언어로 안 오면 감춘다」는 **지금도 실제로 작동하는 방어**다 —
모델을 바꿔서 해결된 문제가 아니라, 모델과 무관하게 남는 문제라는 것이 오히려 증명됐다.

### P2. 완성도 — "구현 완료, 검증 진행 중"
52개 태스크 중 **48개 구현 완료** — `review` 38 + `done` 10 (2026-08-20 재집계).
`review`는 구현·테스트가 끝나고 **최종 실확장 확인만 남은** 상태, `done`은 실확장까지 확인한 상태다.
🔴 **"100% 완료"라고 쓰지 않는다.** 시연 영상이 그 증거가 된다.

### 2. 문제 — "번역은 됐는데, 관계가 상했다"

세 문장을 나란히 놓는다. **설명하지 않고 보여준다.**

| 내가 쓴 것 | 번역기 결과 | 상대가 받은 느낌 |
|---|---|---|
| 반드시 오늘까지 배포해야 합니다 | The rollout **must** be completed today. | 명령·질책 |
| 기획서도 확인 부탁드려요 | Please review the **product spec**. | 🔴 **다른 문서를 봤다** |

- 🔴 두 번째 줄은 **실측이다.** 「기획서」를 서로 다른 번역기가 `product spec` / `project plan`으로
  옮겼다. 톤 문제가 아니라 **무엇을 하라는지가 바뀌었다.**
- 한 줄 요약: **"기존 번역기는 '틀리지 않았는지'를 아무도 확인하지 않는다."**

### 3. 왜 기존 도구로 안 되나

| 도구 | 하는 일 | 못 하는 일 |
|---|---|---|
| 번역기 | 언어 변환 | 톤·긴급도·상대 맥락 · **검증 없음** |
| 문법 교정기 | 문장 다듬기 | 언어 간 오해 |
| LLM 챗봇 | 다 되지만 | 창을 옮겨야 함 · 회사 메시지를 붙여넣어야 함(**보안**) |

→ **"쓰던 창에서, 보내기 전에, 검증까지."**

### 4. 해결 — 세 축

1. **보내기 전** — 긴급도 판정 · 톤 교정 · **역번역으로 되읽기**
2. **받은 뒤** — 수신 해독(직역 / 실제 의도 / 체감 긴급도 / 요구 행동)
3. **보낼 때** — 퇴근 요정(상대 현지 시각·공휴일) · 회의 시간 · 예약

> 🔴 발표 문구: **"AI가 고쳐 주는 게 아니라, 보내기 전에 한 번 더 보여줍니다."**

### 5. 데모 (15초 영상 삽입)
- 영상만 재생하고 말을 얹지 않는다.
- 뒤에 한 줄만: **"드래그 → 클릭 → 확인 → 적용"**

🔴 **영상에서 보여줄 핵심 컷은 「같은 문장, 상황 3종」이다** (2026-08-20 실사용 확인).
말투 이름으로 설명하지 말고 **쓰는 상황**으로 말한다 — 그쪽이 훨씬 빨리 이해된다.

원문: 「바쁘신 와중에 죄송한데요, … API 문서 초안을 이번 주 금요일까지 공유해 주실 수 있을까요?
팀 리뷰가 다음 주 월요일이라서요.」

| 고른 것 | 결과 | 쓰는 곳 |
|---|---|---|
| 부드럽게 | `I apologize for interrupting your busy schedule, but could you please share …?` | 외부 협력사·이메일 |
| 직접적으로 | `Please share the draft API documentation … as the team review is scheduled for next Monday.` | 사내 메일 |
| 짧게 | `Could you share the API doc draft …? Team review is next Monday.` | Slack·Teams |

🔴 **두 축이 서로 반대 방향으로 단조다** — 정중함은 부드럽게>직접적으로>짧게, 길이는 그 반대.
그리고 **세 결과 모두에 「금요일」과 「월요일」이 남아 있다.** 톤을 바꿔도 사실은 안 바뀐다는 것이
이 컷의 요점이다.

### 5-2. 🔴 왜 무조건 공손하게 풀지 않는가

**GPT에게 우리 결과와 다른 번역기를 나란히 놓고 채점시켜 봤다.** 원문: "배포는 반드시 오늘까지
해야 합니다. 늦어서 죄송하고, 기획서도 확인 부탁드려요."

| | 우리 | 다른 번역기 |
|---|---|---|
| 표현 | "The deployment **must be completed** by the end of today." | "**Please ensure that** the deployment is completed… **appreciate your understanding**" |
| GPT 채점 — 공손함 | ★★☆☆☆ | ★★★★★ |
| GPT 채점 — **긴급성** | **★★★★★** | ★★★☆☆ |

🔴 **채점표가 스스로 답을 말한다.** 상대는 공손함을 얻은 대신 **긴급성을 깎아 먹었다.**
원문이 "반드시 오늘까지"인데 "부탁드립니다"로 풀리면 **오늘 안 해도 되는 것처럼 읽힐 위험**이
생긴다.

🔴 **그래서 강도를 «사용자가» 고르게 한다** (Spec 필수 1). 긴급도는 **압박**을, 캐주얼은
**격식**을 정한다 — 서로 다른 축이다. 같은 원문을 네 조합으로 실측했다 (2026-08-18, `gpt-4o`):

| | 캐주얼 OFF | 캐주얼 ON |
|---|---|---|
| **CRITICAL** | must be completed **by today** | we need to deploy this **by today** |
| **LOW** | could you ensure… **by today** when you get a chance? | **Hey,** could you make sure to deploy this **by today**? |

**마감(`by today`)이 네 칸 모두에 살아 있다** — 바뀌는 것은 요청의 «틀»뿐이고 사실은 절대 바뀌지
않는다. 이것이 "무조건 딱딱하게 만든다"와 다른 점이다.

🔴 **"완곡한 쪽이 더 좋은 번역"이라는 전제 자체를 검증했다.**
- 미국·호주·캐나다는 세계에서 가장 **저맥락(low-context)** 문화다(에린 마이어 『컬처맵』).
  "이해가 안 되면 그건 내 잘못"이 기본 태도이지, 돌려 말하는 문화가 아니다.
- 미국 비즈니스 이메일 가이드들이 실제로 권하는 것은 "직설이냐 정중이냐 택일"이 아니라
  **"정중하되 마감을 구체적으로 못 박으라"**다 ("ASAP" 대신 "by 4 PM today").
  우리 결과는 이미 `by the end of today`로 그 기준을 충족한다.

> 발표 문구: **"정중함과 정확함 중 하나를 골라야 한다면, 우리는 정확함을 택했습니다."**

🔴 **정직하게 덧붙일 한계**: 우리가 상정한 상대는 **함께 일하는 해외 팀**(상황 템플릿이
코드리뷰·장애 대응·일정 조율·진행 보고 넷이다)이지, 영업 대상 고객이 아니다.
**관계 유형(동료/파트너/고객)을 구분하는 축은 아직 없다** — 11번 슬라이드에 한계로 적었다.

### 6. 🔴 차별점 — "우리는 AI를 믿지 않습니다"

**이 덱에서 가장 강한 슬라이드.** 전부 이번 주에 실제로 잡은 결함과 그 방어책이다.

| 우리가 만든 검증 | 왜 |
|---|---|
| **역번역이 내 언어로 안 오면 감춘다** | 실측: 한→중 교정에서 역번역이 **중국어로** 나왔다. 확인용인데 확인이 안 된다 |
| **없는 이름·호칭을 만들면 경고** | 실측: 「싱싱」이 중국어에서 `上晦先生/女士`로 바뀌었다 |
| **지어낸 마감·회의를 막는다** | 모델이 없는 약속을 만들면 `[마감 시각]` 자리표시자로 비워 두고, 코드가 대조한다 |
| **AI가 실패하면 실패했다고 쓴다** | 원문을 그대로 두고 **빨간 「교정하지 못했어요」**를 띄운다 — 조용히 넘기지 않는다 |
| 🔴 **문체가 «의미»를 바꾸지 못하게 막는다** | 실측: 「배포하셔도 됩니다」(**허가**)가 말투를 켜자 `Could you proceed?`(**요청**)로 뒤집혔다. 보존 규칙이 마감·숫자·행동만 잠그고 **화행을 안 잠갔다** → 규칙에 추가했다 |

> 발표 문구: **"LLM은 확률적입니다. 그래서 프롬프트로 부탁하지 않고, 결과를 코드가 검사합니다."**

🔴 심사에서 가장 잘 먹힐 지점이다 — **AI 제품인데 AI를 의심하는 설계**를 보여준다.

🔴 **마지막 줄은 특히 세다.** 「번역이 틀렸다」가 아니라 **「번역은 맞는데 «누가 누구에게»가
바뀌었다」**는 결함이고, 번역 품질 지표로는 절대 안 잡힌다. 우리가 왜 결과를 코드로 검사하는지
한 문장으로 설명해 준다.

### 9. 기술 아키텍처

```
크롬 확장 (MV3)                    Firebase
┌────────────────────┐            ┌──────────────────┐
│ In-page 팝업        │            │ Functions        │
│ Side Panel          │──[토큰]──▶ │  /refineV1       │──▶ LLM
│ (React 18 + Vite 5) │            │  /teamV1         │  (OpenAI)
└────────────────────┘            │ Firestore        │
         │                        │  (카운트·용어집만) │
         └── Web Dashboard ───────▶└──────────────────┘
```

- **단일 통합 호출** — 교정·긴급도·역번역·용어집·누락 검사를 **한 번에** 받는다 (Spec §6-3)
- 🔴 **한도에 걸려도 멈추지 않는다** — 지금은 **OpenAI**(`gpt-4o`). 한도(`quota`)에 걸리면
  **Gemini → `gpt-4.1`로 자동으로 넘어간다.** `src/core/refine/providers/`가 **같은 payload·같은
  반환 JSON 계약**을 쓰기에 가능하고, 어느 쪽이 답했는지는 응답의 `providerUsed`·`modelUsed`에 남는다
  - 🔴 근거는 실측이다 — **한도가 모델별로 따로**라 같은 키인데 `gpt-4o`가 0일 때 `gpt-4.1`은
    별도 한도를 갖는다(응답 헤더로 확인)
  - 🔴 넘기는 조건은 좁다: **`quota`일 때만** · 요청이 provider를 **명시하지 않았을 때만**.
    네트워크·형식 오류로는 넘기지 않는다 — 두 번 불러도 같은 이유로 실패한다
  - 순서표는 **한 파일**([`failover.js`](../src/core/refine/failover.js))에만 있고 프록시와 서버가
    그 파일을 함께 임포트한다 → 두 곳이 어긋날 수 없다
- 🔴 **API 키는 확장에 없다.** 확장은 **Firebase ID 토큰**만 들고 우리 서버를 부르고, LLM 키는
  Secret Manager에만 있다. 서버가 토큰을 검증하고 **사용자별 일일 상한**까지 센다
- **순수 코어** — 판정 로직은 네트워크를 모르는 순수 함수라 확장·서버가 **같은 코드**를 쓴다

## 발표 대비 — 나올 질문과 답

| 질문 | 답 |
|---|---|
| "GPT한테 시키면 되지 않나?" | 창을 옮겨야 하고, **회사 메시지를 붙여넣어야** 한다. 우리는 쓰던 창에서 하고 **본문을 저장하지 않는다** |
| "번역 품질이 더 좋나?" | 🔴 **"더 좋다"고 말하지 않는다.** 우리 강점은 품질이 아니라 **검증**이다 — 6번 슬라이드로 답한다 |
| "AI가 틀리면?" | 틀린다고 전제하고 만들었다. 실패를 **감지해서 화면에 띄운다** |
| "모델은 뭘 쓰나?" | **OpenAI `gpt-4o`**. 개발 중에는 한도 때문에 Gemini를 썼고, **교체 지점이 한 파일**이라 프롬프트·검증을 그대로 두고 바꿨다 |
| "키가 확장에 들어 있지 않나?" | 없다. 확장이 가진 것은 **로그인 토큰**뿐이고, LLM 키는 Secret Manager에만 있다. 서버가 토큰을 검증하고 사용자별 일일 상한을 센다 |
| "수익 모델은?" | 개인 무료 / 팀 구독(용어집 동기화 + 건강도 리포트) + 인앱 포인트 |
| "너무 직설적이지 않나?" | 원문이 긴급하면 **긴급하게 전한다**(필수 1). 완곡하게 풀면 마감이 흐려진다 — 5-2번 슬라이드로 답한다. 다만 **고객 응대용 격식 축은 아직 없다**고 인정한다 |
| "실사용자 데이터는?" | 🔴 **없다고 답한다.** 10일 해커톤이고, 대시보드는 **우리 사용 기록**이다 |
