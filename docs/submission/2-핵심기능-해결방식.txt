[핵심 기능]

1. 보내기 전. 문장을 드래그하면 그 자리에 팝업이 뜬다. 긴급도는 AI가 먼저 판정해 보여주고 사용자는 다를 때만 덮어쓴다. 격식은 수신자마다 기본값을 두고, 선호 말투 5종(직접적으로·부드럽게·짧게·결론 먼저·근거를 함께)은 사이드 패널에서 한 번 정하면 계속 적용된다. 메시지마다 설정을 다시 만지게 하지 않는다. 같은 요청문이 부드럽게에서는 I apologize for interrupting your busy schedule로, 짧게에서는 Could you share the API doc draft?로 갈렸다. 정중함과 길이는 반대로 움직였지만 마감일은 세 결과 모두에 남았다. 오해를 부를 표현은 따로 짚고, 감정이 실린 하소연은 실행 가능한 티켓 문장으로 바꿔 준다.

2. 받은 뒤. 받은 메시지를 직역, 실제 의도, 체감 긴급도, 요구 행동으로 분해한다. "a few minor comments"가 실은 접근 방식 재검토 요구인 경우처럼, 표면과 실제가 갈리는 지점을 짚는다.

3. 보낼 때. 상대 현지 시각을 항상 띄우고, 퇴근 시간대나 공휴일이면 발송을 미루자고 제안하고, 회의 시간은 양쪽 근무 시간이 겹치는 구간에서 추천한다.

화면은 셋이다. 쓰던 페이지 위의 팝업, 설정·용어집을 담는 사이드 패널, 팀 지표를 보는 웹 대시보드. 창을 옮기지 않는 것이 전제라 교정은 팝업에서 끝난다.

[해결 방식]

1. 의미 변질 방지 — 번역이 뜻을 바꾸는 문제. LLM은 확률적이라 프롬프트로 부탁하는 것만으로는 잠기지 않는다. 그래서 결과를 코드가 검사한다. 역번역이 상대 언어로 나오는 결함을 실측했는데, 프롬프트를 네 번 고쳐도 실패했고 재현도 간헐적이었다. 코드가 언어를 판정해 내 언어가 아니면 감추고 만들지 못했다고 쓴다. 같은 방식으로 원문에 없는 이름과 호칭, 임의로 채워진 마감 날짜, 허가를 요청으로 뒤집는 화행 역전을 막는다.

2. 파편화와 유출 차단 — 도구가 흩어져 있고 창을 옮겨야 하는 문제. 교정·해독·용어집·시간대가 한 팝업 안에 있다. 본문은 서버·DB·로그 어디에도 저장하지 않고 올라가는 것은 정수 카운트뿐이라, 기밀이든 아니든 처리 경로가 같고 정보 등급을 매번 판단할 필요가 없다. 나아가 API 키·카드번호·주민번호 같은 값은 브라우저 안에서 잡아 전송 자체를 막고, 원할 때만 마스킹해 보낸다. 이 검사는 네트워크를 쓰지 않는다. 보내고 나서 지운다는 말은 성립하지 않기 때문이다.

3. 오해의 비용 최소화 — 오해가 신뢰를 깎는 문제. 신뢰는 늘 맞히는 데서 오지 않고 틀렸을 때 틀렸다고 말하는 데서 온다. 교정이 안 되면 원문을 그대로 둔 채 빨간 「교정하지 못했어요」를 띄운다. 서버가 죽어 예시를 보여 줄 때도 실제 결과가 아님을 밝히고, 로그인이나 한도 문제는 예시로 덮지 않는다.

지금 동작한다. 단위 테스트 775건이 통과 상태이고 서버는 배포돼 있으며, 확장은 실브라우저로 확인했다. 한도에 걸리면 예비 모델로 자동 전환되는 3단계 폴오버가 있어 시연 중에도 멈추지 않는다.
