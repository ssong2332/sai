# 톤 손잡이 테스트 문장 세트

> 2026-08-18 작성. **전제: 언제나 다른 국가의 기업과 협업하는 상황이다.**
> 긴급도(Critical/Normal/Low) × 캐주얼(ON/OFF)이 실제로 문장을 바꾸는지 확인하는 데 쓴다.
>
> 🔴 **연속 호출은 15초 간격.** 분당 5건을 넘으면 「교정하지 못했어요」가 뜬다 (`DemoScript.md` 0절).
> 🔴 **한 번에 손잡이 하나만 바꾼다.** 긴급도와 캐주얼을 같이 만지면 무엇 때문에 바뀌었는지 모른다.

---

## 0. 무엇을 보는가 — 판정표

| 봐야 할 것 | 통과 기준 |
|---|---|
| **사실 보존** | 마감·숫자·요구 행동·부정문이 **모든 조합에서** 살아 있다 |
| **긴급도 반영** | LOW는 질문형 + `when you get a chance` 류가 붙는다 / CRITICAL은 안 붙는다 |
| **캐주얼 반영** | ON이면 친근한 도입부·축약형(`it's`, `we'll`)이 생긴다 |
| **지어내지 않음** | 원문에 없는 마감·회의·인물이 생기지 않는다 |

🔴 **CRITICAL과 NORMAL의 차이는 작다**(실측). 손잡이 확인은 **LOW ↔ CRITICAL**로 한다.

## A. 일정 조율 — 시간대·기간이 걸린 요청

| # | 문장 | 이 문장이 스트레스하는 것 |
|---|---|---|
| A1 | `배포 일정을 조율해야 합니다. 내일 오전에 논의할 수 있을까요?` | 기준 문장. 4조합 실측 완료 |
| A2 | `다음 주 화요일 10시(KST) 스프린트 리뷰를 30분 앞당길 수 있을까요?` | **시각·시간대·기간**이 하나도 안 바뀌어야 한다 |
| A3 | `이번 주 금요일까지 QA 일정을 확정해야 합니다. 오늘 중으로 회신 부탁드립니다.` | **마감이 두 개** — 둘 다 살아남아야 한다 |
| A4 | `그때 말씀하신 시간에 다음 회의를 잡겠습니다.` | 🔴 **없는 정보** — 모델이 시각을 지어내면 실패. `[회의 시각]` 자리표시자가 나와야 한다 |

## B. 장애 대응 — 긴급도가 가장 잘 드러나는 자리

| # | 문장 | 스트레스 |
|---|---|---|
| B1 | `결제 API가 오전 9시부터 응답하지 않습니다. 지금 확인 가능하신가요?` | CRITICAL에서 긴급성이 죽지 않는가 |
| B2 | `핫픽스를 배포했는데 아직 오류율이 3% 남아 있습니다. 롤백 여부를 30분 안에 결정해야 합니다.` | **숫자 2개 + 마감** 동시 보존 |
| B3 | `어제 장애는 우리 쪽 설정 실수였습니다. 늦게 알려드려 죄송하고, 재발 방지책은 내일 공유드리겠습니다.` | **사과 압축** — 사과가 하나만 남아야 한다 |
| B4 | `이번 지연은 우리 쪽 문제가 **아닙니다**. 외부 API 변경 때문입니다.` | 🔴 **부정문 보존** — 부정이 사라지면 책임이 뒤집힌다 |

## C. 코드 리뷰 — 거절·완충어가 섞이는 자리

| # | 문장 | 스트레스 |
|---|---|---|
| C1 | `이 PR은 테스트가 없어서 머지하기 어렵습니다. 테스트 추가 후 다시 요청해 주세요.` | **거절**이 완곡해지다 사라지지 않는가 |
| C2 | `리뷰 몇 가지 남겼는데 대부분 사소합니다. 다만 인증 부분은 반드시 고쳐야 합니다.` | 🔴 `mostly minor`가 **필수 수정을 덮지 않아야** 한다 |
| C3 | `머지 전에 마이그레이션 스크립트를 한 번만 더 봐 주실 수 있을까요?` | 이미 부탁형 — LOW에서 더 부드러워지는가 |

## D. 진행 보고 — 숫자와 용어집

| # | 문장 | 스트레스 |
|---|---|---|
| D1 | `2분기 목표 대비 진행률은 72%입니다. 나머지는 8월 말까지 마무리하겠습니다.` | **퍼센트·날짜** 보존 |
| D2 | `요청하신 기획서 초안을 첨부합니다. 검토 후 의견 주시면 반영하겠습니다.` | 🔴 **용어집** — 「기획서」가 등록한 낱말로 나오는가 |
| D3 | `배포는 오늘까지 해야 합니다.` | 🔴 **언어별 용어집** — 중국어면 `部署`, 영어면 `rollout` |

## E. 이름·역번역 방어

| # | 문장 | 대상 언어 | 스트레스 |
|---|---|---|---|
| E1 | `싱싱님, 배포는 반드시 오늘까지 해야 합니다. 늦어서 죄송하고, 기획서도 확인 부탁드려요.` | 중국어 | **이름 보존** — 「싱싱」이 다른 호칭으로 바뀌면 경고가 떠야 한다 |
| E2 | 위와 같은 문장 | **일본어** | 🔴 **역번역 언어** — 한→일은 역번역이 일본어로 오는 것이 실측됐다. 「역번역을 확인할 수 없어요」가 떠야 정상 |

## F. 수신 해독용 (상대가 보낸 것처럼)

| # | 문장 | 스트레스 |
|---|---|---|
| F1 | `I have a few minor comments on the deck. Let's circle back when you have bandwidth.` | `minor`·`bandwidth`가 완충어임을 풀어내는가 |
| F2 | `Could you take a look when you get a chance? No rush.` | 🔴 **완곡한 요청 뒤의 실제 마감**을 짚어내는가 |
| F3 | `We'll need to align on the deployment schedule before Friday.` | `align on` 관용구 해석 + 마감(Friday) 추출 |

## 부록 — GPT 지적 검증 (2026-08-18)

**GPT 주장**: *"엔지니어끼리는 `We need to **align on** the deployment schedule`이라고 쓴다."*

| 확인 | 결과 |
|---|---|
| `align on`이 우리 표현 시드에 있는가 | 🔴 **없다** (영어 34건 중 미포함) |
| 우리 출력(`coordinate`)이 틀렸는가 | 🟢 **아니다** — `coordinate`도 자연스럽다. `align on`이 IT 조직에서 더 흔할 뿐 |
| 표현을 실어 주면 모델이 쓰는가 | 🔴 **안 쓴다** (실측) |

🔴 **가설이 틀렸다는 것을 실측으로 확인했다.** 처음에는 「시드 34개 중 앞 6개만 실려서
(`MAX_EXPRESSIONS = 6`) 일정 조율에 맞는 `let's sync`·`touch base`가 한 번도 안 나간다」가
원인이라고 봤다. 그래서 **맞는 표현 4개를 직접 실어 보내는 실험**을 했는데 — 결과는 그대로
`Hey, could we discuss…`였고 **하나도 쓰이지 않았다.**

원인은 목록이 아니라 **규칙 문구**다. `casualToneRules`의
「*use one ONLY where it fits naturally — never force one in, and using none of them is fine*」이
충분히 강해서 모델이 **항상 「하나도 안 쓰기」를 고른다.**

🔴 **그래서 더 밀지 않는다.** 그 문구를 풀면 업무 메시지에 관용구가 억지로 끼어든다 —
캐주얼 토글은 이미 도입부·축약형으로 **눈에 보이는 차이**를 만들고 있고, 그 이상은
얻는 것보다 잃는 것이 크다. (`MAX_EXPRESSIONS = 6`의 주석 「실측 아님, 보수적 상한」은
이제 실측됐다: **상한을 늘려도 달라지지 않는다.**)
