# 처리방침 추가 문안 — GitHub 아이디 불러오기 (초안, 미게시)

## 금지
- 🔴 **`FEATURES.githubLookup`을 켜기 전에는 게시하지 않는다.** 없는 기능을 방침에 적으면 방침이 틀린다.
- 🔴 이 문안만으로 기능을 켜지 않는다 — 다시 켤 조건 3개(아래 「켜기 순서」)를 모두 채운다.
- 🔴 법률 검토 전 확정 문구로 쓰지 않는다(L19와 같은 조건).

## 근거 — 코드가 실제로 하는 일 (2026-10-27 확인)

| 항목 | 내용 | 근거 |
|---|---|---|
| 누가 입력하나 | 이용자가 **상대방(제3자)의 GitHub 아이디**를 수신자 폼에 입력 | `src/sidepanel/App.jsx` `lookup` |
| 어디로 가나 | 이용자 브라우저 → `api.github.com` **직접**. 운영자 서버(Worker·Firestore)를 거치지 않음 | `src/lib/githubClient.js` `API_ROOT` |
| 무엇을 읽나 | 공개 프로필(이름·위치), 공개 활동 최대 300건(`events/public` 100건 × 3장) | `fetchUserProfile` · `fetchPublicEvents` · `GITHUB_EVENT_PAGES = 3` |
| 무엇이 남나 | 상대 이름(폼에 채워짐) · GitHub 아이디 · 이용자가 고른 소통 태그 — **수신자 목록에 저장, 기기에만** | `src/lib/recipients.js` `githubLogin` |
| 무엇이 안 남나 | 공개 활동 원문(코멘트 본문 등) — 메모리에서 분석 후 버림. 위치는 화면 안내로만 쓰고 저장 안 함 | `App.jsx` 「`events`는 여기서만 산다」 주석 · `core/github/index.js` 반환값에 본문 없음 |
| 자동 적용 | 아니오 — 제안 태그는 화면에 켜진 채 보이고 **이용자가 저장을 눌러야** 들어감 | `App.jsx` `lookup` 주석(Spec 필수 9) |
| GitHub 연결(선택) | 🔴 **지금 화면에 없음**(`GitHubLinkRow` 미사용). 되살리면: Device Flow 토큰, **권한 범위 없음**(공개 데이터만, 비공개 저장소 못 봄). 용도는 요청 한도(시간당 60 → 5,000)뿐. 기기에만 저장 | `githubClient.js` 헤더 · `STORAGE_KEYS.GITHUB_TOKEN` |

## 넣을 자리와 문안

### ① 1절 표에 한 행 추가 (「팀 기능(선택)」 아래)

| 구분 | 항목 | 목적 | 저장 위치 |
|---|---|---|---|
| GitHub 불러오기(선택) | 이용자가 입력한 상대방의 GitHub 아이디, 그 계정의 공개 프로필 이름 | 받는 사람 등록을 돕고 소통 태그를 제안 | 이용자 기기(`chrome.storage.local`)에만 |

### ② 3절 끝에 문단 추가

> **GitHub 아이디 불러오기(선택).** 받는 사람을 등록할 때 상대방의 GitHub 아이디를 입력하면, 이용자의
> 브라우저가 GitHub(GitHub, Inc., 미국)에 직접 접속해 그 계정의 **공개** 프로필과 공개 활동 기록(최대 300건)을
> 읽습니다. 이 요청은 운영자 서버를 거치지 않으며, 운영자는 입력한 아이디나 읽은 내용을 받지 않습니다.
> 공개 활동 기록은 이용자 기기에서 소통 경향(답장 길이·시간대 등)을 계산하는 데만 쓰고 바로 버리며, 코멘트
> 내용은 저장하지 않습니다. 기기에 남는 것은 상대방의 이름, GitHub 아이디, 그리고 이용자가 **직접 확인해
> 저장한** 소통 태그뿐입니다. 비공개 저장소나 비공개 정보는 읽지 않습니다.
>
> 이 기능은 상대방이 GitHub에 공개한 정보를 이용합니다. 상대방이 원하지 않는 경우 사용하지 마시고, 등록한
> 정보는 언제든 받는 사람 목록에서 수정하거나 삭제할 수 있습니다.

### ③ 3절 GitHub 연결 문장 (② 바로 뒤) — 🔴 **연결 버튼을 되살릴 때만** 넣는다

지금 코드에는 연결 화면(`GitHubLinkRow`)이 있지만 **어디에서도 렌더하지 않는다**(`App.jsx` 「`AccountCard`에 한 줄만
되살리면 된다」 주석). 연결 없이도 조회는 된다(시간당 60회). 연결 줄을 되살리는 경우에만 아래를 넣는다.

> GitHub 계정을 연결하면(선택) GitHub가 발급한 접근 토큰이 이용자 기기에만 저장됩니다. 이 토큰은 권한
> 범위 없이 발급되어 공개 정보 조회 한도를 늘리는 데만 쓰이며, 운영자에게 전송되지 않습니다. 연결을 끊거나
> 확장 프로그램을 삭제하면 기기에서 삭제됩니다.

### ④ 5절(처리 위탁과 국외 이전) — 추가하지 않음 (판단 근거)

| 질문 | 판단 | 이유 |
|---|---|---|
| GitHub가 위탁사인가 | 아니오(추정) | 운영자가 맡기는 처리가 아니라 이용자 기기가 공개 API를 직접 부른다 |
| 국외 이전인가 | 운영자 기준 아니오(추정) | 운영자가 정보를 받거나 넘기지 않는다. 다만 ②에 「GitHub, Inc., 미국」을 명시해 알린다 |

🔴 위 두 줄은 **추정**이다 — 법률 검토에서 확인할 질문으로 넘긴다.

## 확인할 것 (법률 검토 질문)
1. 이용자가 제3자의 **공개** 정보를 조회·기기 저장하는 경우, 운영자가 제3자에게 고지할 의무가 있는가.
2. ④ 판단(위탁·국외 이전 아님)이 맞는가.
3. 「상대방이 원하지 않는 경우 사용하지 말라」는 안내로 충분한가.

## 켜기 순서
1. `FEATURES.githubLookup = true` 빌드로 실확장 확인(수신자 폼 조회 → 태그 제안 → 저장 → 연결/해제)
2. 이 문안을 `dashboard/public/privacy.html`에 반영 + 시행일 갱신 → 사용자 승인
3. 호스팅 배포(사용자) → 그 뒤 플래그 켠 버전 배포
