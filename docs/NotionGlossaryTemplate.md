# 노션 용어집 템플릿 — 사이 「연동」 가져오기용

> 이 문서는 **노션에 그대로 만들어 쓰는 표**의 설계다. 사이의 `보관함 → 용어집 → 연동`이
> 붙여넣기(CSV/TSV)를 받으므로, 노션에서 이 표를 만들고 **복사해서 붙여넣으면** 그대로 들어간다.

## 🔴 먼저 — 왜 노션 API가 아니라 붙여넣기인가

| 방법 | 필요한 것 | 판정 |
|---|---|---|
| 붙여넣기 (CSV/TSV) | **없음** | 🟢 채택. 노션·Sheets·Excel·Confluence 전부 대응 |
| GitHub 레포 파일 | 이미 있는 권한 | 🟡 가능하나 개발팀 한정 |
| 노션 공식 API | 노션 OAuth 앱 + `client_secret` + 서버 엔드포인트 | 🔴 새 서버 작업 + 동의 화면 심사 |

노션 API는 `client_secret`이 필요해 **확장 번들에 넣을 수 없고**(누구나 뜯어본다) Functions에
새 엔드포인트와 Secret Manager 등록이 따라온다. Slack 연동을 취소했던 것과 **같은 이유**다
(`docs/Tasks.md` S30-slack). 붙여넣기는 그 전부를 건너뛰면서 **도구를 가리지 않는다.**

---

## 1. 노션에 만들 표

노션에서 `/table` → **표(Table)** 를 만들고 열 두 개만 둔다.

| 원문 | 번역어 |
|---|---|
| 배포 | rollout |
| 기획서 | product spec |
| 갈아엎다 | rework from scratch |
| 사이 | *(비움)* |
| 온보딩 | onboarding |

### 열 규칙 (판정표 — 사이가 이대로 읽는다)

| 상황 | 사이의 처리 |
|---|---|
| 두 칸 다 채움 | `원문 → 번역어`로 치환 |
| **번역어를 비움** | 🔴 **원문 유지** — 번역하지 않고 그대로 둔다(제품명·코드네임) |
| 첫 줄이 `원문`·`용어`·`source`·`term` | 머리글로 보고 건너뜀 |
| 같은 원문이 두 번 | 뒤엣것을 버림(어느 쪽이 이기는지 모호한 항목을 만들지 않는다) |
| 세 칸 이상 | 앞 두 칸만 사용 — **메모 열을 자유롭게 둬도 된다** |

> 🔴 **열 순서가 계약이다.** 첫 칸이 원문, 둘째 칸이 번역어다. 노션에서 열을 옮기면 결과가 뒤집힌다.

---

## 2. 가져오는 방법

1. 노션 표에서 **머리글 포함 전체 선택** → `Ctrl+C`
2. 사이 사이드패널 → **보관함 → 용어집 → 연동**
3. 입력창에 `Ctrl+V` → **「확인하기」**
4. 미리보기에서 **개수와 건너뛴 줄 수**를 확인 → **「개인 용어집에 추가」**

> 🔴 노션 표를 복사하면 **탭 구분(TSV)** 으로 붙는다. 사이는 탭을 쉼표보다 먼저 보므로
> `Seoul, Korea`처럼 **값 안에 쉼표가 있어도 쪼개지지 않는다.**

> 🔴 한 번에 **200줄**까지다. 넘으면 미리보기가 "200개까지만 받아요"라고 알린다.

---

## 3. 팀에서 함께 쓰려면

가져오기는 **개인 용어집**으로 들어간다(우선순위: 개인 > 팀 > 기본 AI).
팀 전체가 같은 용어를 쓰려면 `보관함 → 용어집 → 팀`에서 등록한다 — 팀원 모두에게 보이고
모두가 고칠 수 있다.

**권장 운용**
- 노션 표 = **원본**(팀이 함께 관리, 논의·히스토리가 남는다)
- 사이 팀 용어집 = **적용본**(교정에 실제로 실린다)
- 노션이 바뀌면 다시 복사해 붙여넣는다 — 🔴 **자동 동기화가 아니다.** 이 문서를 읽는 사람이
  그 사실을 알아야 "왜 안 바뀌지"가 생기지 않는다.

---

## 4. 채울 때 도움이 되는 분류

표에 넣을 만한 것들. 🔴 **문장이 아니라 낱말·짧은 구**만 넣는다 — 용어집은 치환 규칙이지
번역 메모리가 아니다.

| 분류 | 예 |
|---|---|
| 제품·기능 이름 | 사이 *(원문 유지)* · 퇴근 요정 → off-hours reminder |
| 사내 은어 | 갈아엎다 → rework from scratch · 태우다 → run |
| 문서 종류 | 기획서 → product spec · 요건서 → requirements doc |
| 조직·직함 | 실 → division · 파트 → part |
| 자주 틀리는 번역 | 배포 → rollout *(deployment가 아님)* |

---

## 5. 알려진 한계

- 🔴 **단방향이다.** 사이 → 노션으로 내보내는 기능은 없다.
- 🔴 **자동 갱신이 없다.** 노션을 고쳐도 사이는 모른다. 다시 붙여넣어야 한다.
- 중복 원문은 **먼저 나온 것**이 남는다 — 노션에서 정리하는 편이 낫다.
- 200자를 넘는 값은 잘린다(본문이 용어를 가장해 들어오는 것을 막는 상한).
